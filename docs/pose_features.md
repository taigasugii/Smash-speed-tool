# フォームの数値（姿勢推定と特徴量）

ROADMAP の E 章（フォームと姿勢）で作った処理の、式と理由をまとめる。
数値はすべて側方の撮影（ラケットを持つ腕の側から、打つ向きに直交、距離 6〜8 m、高さ 1.2〜1.5 m、水平）を前提にしている。
画像に写った 2 次元の位置から出すので、カメラに向かう向き（奥行き）の動きは見えない。どの値がその影響を受けるかを、各項に書いた。

## 1. 姿勢推定（E1、`smash_speed/pose.py`）

### 関節の決まり

関節は COCO の 17 点（鼻・両目・両耳・両肩・両肘・両手首・両腰・両膝・両足首）にそろえる。
RTMPose はもともと 17 点、MediaPipe Pose は 33 点のうち同じ所の 17 点を使う（`MEDIAPIPE_TO_COCO`）。
信頼度は 0〜1（RTMPose は 1 を超える値を 1 に収める、MediaPipe は visibility と presence の小さい方）。

### モデル

| モデル | ライセンス | 重み | GPU | 入れ方 |
|---|---|---|---|---|
| RTMPose（rtmlib） | Apache 2.0（rtmlib・RTMPose のコード） | `balanced` で人の検出（YOLOX-m）と関節（RTMPose-m）で約 100 MB。初めて使うときに OpenMMLab の配布元から取ってくる | ONNX なので `accel.make_session` に載せ替え、デスクトップでは DirectML | `pip install --no-deps rtmlib tqdm`（下の注意） |
| MediaPipe Pose Landmarker | Apache 2.0（コードと重み） | lite 約 6 MB・full 約 9 MB・heavy 約 30 MB。`ckpts/pose/` に取ってくる | Python 版は CPU だけ | `pip install -e .[pose]` |

- rtmlib は `onnxruntime`（CPU 版）を一緒に入れようとする。Windows で `onnxruntime-directml` と両方入ると壊れる（`docs/gpu.md`）ので、
  `--no-deps` で入れる。
- RTMPose の重みは body7（COCO・AI Challenger・CrowdPose・MPII・Halpe など 7 つのデータの集まり）で学習されている。
  コードは Apache 2.0 だが、学習に使ったデータには研究用に限るものが含まれる。個人の解析に使う分には問題になりにくいが、
  解析の結果やモデルを配るときは確かめ直す。
- どちらのモデルを使うかは、手で付けた関節（約 200 コマ）との PCK で決める（下）。まだ人が付けていないので決めていない。

### 打つ人の選び方

1 コマに複数の人（相手・審判・通りかかった人）が写ることがある。最初のコマは関節の範囲（外接の四角の面積）がいちばん大きい人
（側方の近くから撮るので、打つ人がいちばん大きく写る）、次のコマからは前のコマの打つ人の中心にいちばん近い人を選ぶ。
画像の幅の 15% より離れた人は選ばず、10 コマ続けて見失ったら選び直す。

### 信頼度の低い関節

信頼度が 0.3 より低い関節は欠け（NaN）にする。体の陰になった非利き腕・奥の脚は信頼度が下がるので、
推定の位置をそのまま使うと角度が大きく狂う。3 コマ以下の欠けは前後から直線で埋め（60fps で 0.05 秒。手首の速い動きでも
この長さなら形が大きく変わらない）、それより長い欠けは残して、その関節を使う特徴量を「出せない」にする。

### 精度（PCK）

PCK（Percentage of Correct Keypoints）：推定と手で付けた位置の距離が「胴体の長さ × α」以内の関節の割合。α = 0.2 を使う。

- 胴体の長さ = 手で付けた肩の中点と腰の中点の距離。人の大きさ（カメラからの距離）によらず比べられる。
  側方の撮影では肩幅が向きによって 0 近くまで縮むので、COCO の頭の大きさや肩幅ではなく胴体の長さにした。
- 推定で欠け・信頼度が低い関節は外れに数える（「見つけられなかった」も間違いのうち）。
- 隠れている（visible = 1）関節は、既定では数えない（人が付けた位置も推測なので）。

手で付けた関節の CSV（`pose.LABEL_COLUMNS`）は 1 行 1 関節：

```
video,frame,t_s,joint,x,y,visible
clear_01.mp4,612,10.200000,right_wrist,1043.5,402.0,2
```

`frame` は動画のコマの番号、`t_s` はその実時間 [s]（比べるときは時刻で推定のコマと合わせる）、`joint` は `pose.KEYPOINTS` の名前、
`visible` は COCO と同じ（0 付けていない／1 隠れているが位置は推測／2 見える）。

付け方の目安：200 コマは、ショット 20 本 × 10 コマ（構え・テイクバック・振り出し・インパクトの前後 3 コマ・フォロースルー）にすると、
速く動いてぶれたコマも含まれる。関節は骨の中心（肩は肩峰ではなく腕の付け根の中心）に付ける。

```
python -m smash_speed.pose estimate clear_01.mp4 --model rtmpose --start 10 --end 12 --out rtmpose.npz
python -m smash_speed.pose estimate clear_01.mp4 --model mediapipe --start 10 --end 12 --out mediapipe.npz
python -m smash_speed.pose pck labels.csv rtmpose.npz mediapipe.npz
```

合成の骨格（`synth_pose.py`）に正規分布の揺れ σ を足すと、誤差は Rayleigh 分布になり、PCK = 1 − exp(−(αL)²/2σ²) になることを
テスト（`tests/test_pose.py`）で確かめている。

## 2. 前処理（E1b、`smash_speed/pose_prep.py`）

### 打点の時刻

1. 利き腕の手首の、画像の上の速さ（3 コマの移動平均の後の差分）が最大の時刻 t_w を出す（前後のコマに放物線を当てて、コマの間まで細かくする）。
2. t_w の ±0.15 秒に打球音の立ち上がり t_a があれば、打点 = t_a − d / 343（d は打つ人からカメラ（マイク）までの距離 [m]、
   音速 343 m/s。7 m なら 20 ms ＝ 60fps で 1.2 コマ）。打球音は時刻が正確（1 ms 以下）なので、あればこれを使う。
   手首の最大は「どの音がこのスイングの音か」を選ぶのに使う（相手の打球・隣のコートの音を外す）。
3. 音がなければ、打点 = t_w + `wrist_offset_s`。手首は打点の少し前に最も速くなる（合成のスイングでは 0.03 秒前）。
   この差を 0 のままにすると、肘は打点の 0.03 秒前の、まだ伸び切っていない角度になる（合成で 140° のスイングが 125° と出た。
   `tests/test_form.py`）。手で付けた打点のコマから `calibrate_wrist_offset` で差の中央値を決めて使う。

手で付けた打点と比べるには `impact_errors`（誤差の平均・中央値・最大を、秒とコマで出す）。

### 切り出し・反転・正規化

- 切り出し：打点の前 1.0 秒〜後 0.5 秒（構えからフォロースルー・戻りの始まりまで）。
- 左利き：画像を左右に反転し（x → 幅 − x）、関節の左右の名前を入れ替える。左利きをラケットの腕の側（左）から撮った画像は、
  右利きを右から撮った画像の鏡像なので、反転すると右利きと同じ式がそのまま使える。
- 正規化：腰の中点（両腰の中点）を原点、上を +y、打つ向きを +x にし、胴体の長さ（肩の中点〜腰の中点の、区間の中央値）で割る。
  - 原点を腰にするのは、踏み込み・ジャンプで体ごと動いても、腕・脚の形だけを比べられるようにするため。体の動き（体重移動）は、
    最初のコマの腰の中点からの動き（`hip`）として別に残す。
  - 胴体の長さで割るのは、カメラからの距離・身長が違っても同じ大きさで比べるため。胴体は側方から見ても縮みにくい
    （肩幅・腰幅は向きで 0 近くまで縮む）。コマごとではなく中央値にするのは、前かがみ・推定の揺れで値が動かないようにするため。
  - 打つ向きは「鼻が耳の中点より前にある向き」から決める。ラケットの腕の側から撮れば、右利きはいつも画像の右へ打つ
    （左利きは反転後に右）。カメラを反対側に置いたときも、ここで +x を打つ向きにそろえる。

### 顔のぼかし

`blur_faces`：鼻・目・耳の点の広がりの 1.8 倍（胴体の長さの 0.18 倍より小さければその大きさ）の楕円を、顔の大きさに合わせた
強さでぼかす。画面に出す・書き出す画像に使う（解析そのものはぼかす前の画像で行う）。

## 3. 打点の瞬間の姿勢（E2、`smash_speed/pose_features.py`）

正規化した姿勢（単位は胴体の長さ、時刻は打点が 0）から出す。速さ・角速度は、欠けを直線で埋め、Savitzky–Golay フィルタ
（0.05 秒・2 次。60fps で 5 コマ）でなめらかにしてから差分をとる。打点での値は前後のコマから直線で出す。

| 特徴量 | 式 | 理由・注意 |
|---|---|---|
| 身長（胴体の何倍か） | (胴体 + 太もも + すね) ÷ (0.288 + 0.245 + 0.246) | 身長比にするため。太もも・すねは区間の 90 パーセンタイル（見かけが縮んだコマを避ける）。比は Winter の体節の比 |
| 打点の高さ（身長比） | (手首の高さ − 両足首の中点の高さ) ÷ 身長 + 0.039 | 0.039 は床から足首までの高さの比。ジャンプして打つと 1 を大きく超える |
| 打点の前後（身長比） | 手首の x（腰の中点からの前後）÷ 身長 | 前で打てているか。体の前が正 |
| 肘の角度 | 肩・肘・手首のなす角 | 180° でまっすぐ。腕が画像の面にある（側方から見て、腕を打つ向きに振る）ほど正しい |
| 肩の角度 | 上腕（肩 → 肘）と体の脇の線（肩 → 同じ側の腰）のなす角 | 肩の外転・挙上の代わり。180° で腕が体の線の延長（真上） |
| 膝の角度（前・後ろ） | 腰・膝・足首のなす角 | 前の脚は非利き腕の側。踏み込み・沈み込みの深さ |
| 手首の速さの最大（身長/秒） | 手首の速さの、−0.5〜+0.1 秒の最大 ÷ 身長 | 画像の面の中の速さなので、カメラに向かう向きの速さは入らない。コマの間を飛ばす分、少なめに出る（合成で 60fps 約 13%、120fps 約 9%）ので、同じ fps どうしで比べる |
| 肩幅・腰幅（打点） | \|左肩の x − 右肩の x\| ÷ 区間の最大 | 側方から見ると、横向き（肩の線が打つ向き）で最大、正面向きで 0。回旋の代わりの指標 |
| 胸・腰の回旋 θ | arccos(幅 ÷ 区間の最大) | 横向きから何度回ったか（0〜90°）。正面を越えて回った分と、回る向きの左右は区別できない |
| 捻りの最大・その時刻 | 腰の回旋 − 胸の回旋 の、打点までの最大 | 腰が先に回り、胸が遅れる間の「ずれ」（X-factor の代わり） |
| 捻りが戻る速さ | 捻りの最大の後の、捻りが減る速さの最大 [°/秒] | 胸が腰に追いつく速さ |
| 反対の腕を引く時刻 | 非利き腕の手首が下へ動く速さが最大の時刻 | 体を回す前に反対の腕を引き込めているか |
| 打った後に戻る速さ（身長/秒） | 打点の後 0〜0.5 秒の、腰の中点の速さの最大 ÷ 身長 | 次の球への戻りの速さ |

合成のスイング（`synth_pose.py`）で、正解との差は：肘・肩の角度 2〜3° 以内、膝の角度 2° 以内、打点の高さ・前後 0.02 以内（身長比）、
捻りの最大 3° 以内（`tests/test_pose_features.py`）。カメラの距離 6〜8 m・高さ 1.3〜1.5 m・関節の揺れ 1 px でも、角度は 4° 以内で同じ。

## 4. 動きの順番（E3、`smash_speed/pose_features.py`）

運動連鎖：体の中心から先へ、腰（骨盤）→ 肩（胸）→ 肘 → 手首の順に速さの最大が来ると、先の部分ほど速くなる。
次の 4 つの最大の時刻（−0.5〜+0.1 秒の中）を出し、早い順に並べる。

| 部分 | 何の速さか | 式 |
|---|---|---|
| 腰 | 骨盤の回旋の角速度 | \|dθ_腰/dt\|（θ は腰幅から出した回旋） |
| 肩 | 胸の回旋の角速度 | \|dθ_胸/dt\|（肩幅から） |
| 肘 | 肘が伸びる角速度 | d(肘の角度)/dt |
| 手首 | 手首の速さ | 画像の上の速さ |

- `chain_order`：最大の早い順（例 `pelvis>trunk>elbow>wrist`）。`chain_in_order`：腰 → 肩 → 肘 → 手首の順なら 1。
- `lag_*`：隣り合う最大の時間差 [秒]。
- 回旋は幅から出すので、側方の撮影でしか出せない（正面・斜めからでは幅が回旋をそのまま表さない）。回旋の角速度に絶対値を
  とるのは、正面を越えて回ると幅が増え始め、arccos の値が戻る（向きが分からない）ため。

体重移動：

| 特徴量 | 式 |
|---|---|
| 踏み込み（身長比） | 打点での腰の中点の x − 打点までの最小 の x、÷ 身長 |
| 沈み込み（身長比） | −0.6 秒より前の腰の中点の高さの平均 − −0.6〜+0.1 秒の最小、÷ 身長 |
| 体重移動が最も速い時刻 | 腰の中点が前へ動く速さが最大の時刻（−0.6〜+0.1 秒）。打点との時間差 |

合成のスイングで、最大の時刻は 60fps・120fps とも正解と 0.01 秒以内、順番を崩したスイング（腰を肩より遅らせる）では
`chain_in_order` が 0 になることを確かめている。

## 5. フォームを比べる画面（E4、GUI の「フォームを比べる」）

- 出力の場所の下の `*/form/form_features.csv` をすべて集め、撮った日・動画・時刻の順に並べる。日で絞れる。
- A・B の欄で 2 本を選ぶと、打った瞬間を 0 秒にそろえ、腰の高さと胴体の長さをそろえた棒人間を「重ねる／並べる」で描き、
  時刻のつまみ（−1.0〜+0.5 秒）と「動かす」（4 倍ゆっくり）で動きを比べる。下に、肘・肩の角度、胸の回り、手首の速さの
  時間の変化（A・B の線と、いまの時刻）と、打った瞬間の数字の表（B − A つき）を出す。
- 「速い球と遅い球を選ぶ」：球の速さ（E6）が分かればそれで、なければ手首の速さで、いちばん速いものと遅いものを A・B にする。
- 動画を開いていれば、利き手・カメラまでの距離・モデル（標準 = RTMPose、軽い = MediaPipe）を選んで解析を始められる
  （`python -m smash_speed.form` と `python -m smash_speed.form_table` を裏で実行する）。
